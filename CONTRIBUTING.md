# Contributing or continuing the work

This is an archival handoff, so a fork may be more appropriate than a pull request. No response or collaboration is promised.

Any reported extension should include:

1. the exact claim or open-problem ID being tested;
2. the substrate and independently justified candidate partitions;
3. the frozen operationalization of C1, C2, C3, `tau_0`, `mu*`, and `kappa`;
4. transformation families, thresholds, seeds, parameter ranges, and exclusion rules;
5. all pass, fail, and void outcomes;
6. negative controls, lesions, rescue tests, and hostile competitors;
7. a statement of what the result does **not** establish;
8. code, environment information, raw outputs, and a change log.

Do not overwrite a failed route with a tuned successful version. Preserve the original specification, register the revision separately, and report why the change was made.

Do not describe concordance with another framework as independent validation unless the other framework did not supply the answer the test was meant to derive.
